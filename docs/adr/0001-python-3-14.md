# ADR-0001: Use Python 3.14 for the prototype
- **Status:** Accepted · **Date:** 2026-10-18 · **Decided by:** user · **Log:** D-01

## Context
The prototype has to model money exactly, validate JSON fixtures, run offline, and be quick to build and
easy to read for reviewers. The candidates were Python, TypeScript/Node, Kotlin/JVM and Go.

## Decision
Python 3.14 (the current stable release), managed with uv (D-06). Money uses `decimal.Decimal`; models and
validation use pydantic (ADR-0003); tests use pytest and hypothesis.

Why: decimal arithmetic is in the standard library; the data-modelling and validation ecosystem is mature; LLM
SDKs are first-class; iteration is fast; and the code reads easily in review.

## Depends on (team & context)
This choice is about the prototype. A real team could reasonably pick differently:
- **Team experience:** the language the team already ships and reviews well beats marginal technical
  advantages. A TypeScript- or JVM-heavy team should use its own stack.
- **Existing platform:** the languages and shared libraries already in the booking and reshopping estate (GDS/NDC
  connectors, money/currency libraries, observability tooling) pull toward that stack.
- **Ownership and hiring:** who maintains the service after the prototype, and which skills the org hires for.
- **Runtime policy:** approved language versions and base images. 3.14 may be newer than a platform's approved baseline.
- **Performance profile:** reshopping at scale is bound by I/O and supplier rate limits, so Python is adequate. A
  CPU-hot path, such as bulk fare matching, could move to a faster runtime later.

## Consequences
- `requires-python >= 3.14`. Running it needs 3.14; `uv` fetches it if it's missing (network at install time only).
- The newest Python can lag in third-party wheels. This is checked at `uv sync`, and a fallback to 3.13 is cheap if needed.

## Alternatives considered
- **TypeScript/Node:** a good fit for a TypeScript team, but money needs integer minor units or a decimal library.
- **Kotlin/JVM:** BigDecimal and strong typing, but more scaffolding.
- **Go:** simple deployment, but a weaker decimal and validation story.

## Revisit when
The prototype joins an existing codebase or team, or the platform's version policy rules out 3.14.
